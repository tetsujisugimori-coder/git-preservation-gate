# Adapter boundary and one-shot handoff

This is a nonsecret synthetic pilot, not a production custody service. Request and trusted approval are separate inputs. Scope validation is not owner authentication: a caller must establish the approval before supplying it. A self-authored request cannot bootstrap approval. No token, credential or private approval source is published.

Direct mode is preferred on the normal non-admin Windows route. Handoff mode is a one-shot receiver reading a fixed request from a reachable authorized source; it uses the same validated save primitive and records mode/subject/target. No persistent daemon, task registration, port, browser handoff, privilege elevation or ACL modification is installed. Merely calling the direct mode 'handoff' is insufficient: a separately launched receiver must read the specified source and a new request and generate its receipt. When the cloud cannot expose bytes through an approved route, that cross-environment transfer remains BLOCKED/NOT_TESTED rather than inferred from a Windows-local test.

The prototype uses private fresh attempt directories, rejects visible symlinks/reparse ancestors and traversal, and publishes data create-only before a final receipt. Source and destination are bounded local files. Per-call deadlines are cooperative and cannot interrupt arbitrary kernel filesystem hangs; the external finite runner is a separate observed bound. Filesystem atomicity and durable power-loss persistence are not universal guarantees. A malicious concurrent administrator or owner able to replace directories is outside the protected threat model; checks do not establish adversarial race-proof path confinement. Such a target must not be accepted for a strict strong-authenticity risk case.

Plain synthetic text/binary objects are the pilot subjects; no unnecessary ZIP wrapper. CRC is NOT_APPLICABLE for these objects. Bundle/ZIP case-specific validation is not waived: kinds requiring it are unsupported here until a dedicated adapter validates them. Existing Stage1-A bundle tests remain regression evidence, not custody proof for these new objects.

Level1 default-input normalization remains Issue14, not silently introduced into the old contract. Existing ordinary Git work does not require this adapter. An explicit new archive operation needs its own complete scope. Level2/3 cannot be passed using Level1 defaults; confidential/Level3 inputs are unsupported by this limited pilot. No real permit is issued even after byte verification.
