# Gate A/B/C・監査契約 v0.3.0（正式採用承認版）

[規約本文](policy.md) と同じく、所有者が2026-11-24 JSTに正式採用を承認し、PR #25のmainマージ時に発効する契約。Gate A/B/Cの定義、SOLO_STANDARD・STRICT_INDEPENDENTの要件、制御策の実証は [v0.2.0のGate・監査契約](../v0.2.0/gates-and-audit.md) を継承する。分類、P2補訂の追加安全条件の適用範囲、HEAD変更時の再審査は、以下の記載を適用する。

## 追加安全条件と集約

- **Level 1**。通常のGit・GitHub管理で追加保存の指定がない場合、追加Archiveは `NOT_TESTED`・非適用とする。明示された追加保存は別操作として判定する。案件別CI・レビューを続け、対象・操作に結びつく既知の失敗は該当軸に保持する。
- **Level 2**。原物保全の基本検査に加え、喪失・破壊・真正性等の該当リスクに対する保護条件を操作別に固定する。基本検査が当該リスクをカバーする場合はその根拠を記録する。案件契約で必要な保護条件が未成立なら、依存するGate B/Cの成立を保留し、FAIL・BLOCKED・UNKNOWN・NOT_TESTEDは観測結果に応じて区別する。
- **Level 3**。所有者指定または最低Level 3を確定する規約上の根拠と、操作の個別承認を確認する。[v0.2.0 §6](../v0.2.0/policy.md#6-p2補訂-level-3の安全条件決定) の追加安全契約と状態の区別を、v0.3.0で特定した該当リスクに対して適用する。全該当リスクを記録し、追加検査不要とする場合は基本検査で十分な理由と承認を残す。必要な追加検査は事前に固定する。別アカウント・VM等の要否は案件契約に従う。

[v0.2.0 §3](../v0.2.0/policy.md#3-四状態と集約) の状態定義と集約順序を継承する。対象・操作に結びつく既知の必須検査FAILや承認FAILは分類変更後も該当軸と受入に残す。既知の独立性不成立と、別軸の未確認状態も保持する。分類が未確定なら、その分類に依存する保全完了や受入を保留する。

SOLO_STANDARDでは、別セッション・別実行ID・別検証領域を使い、検証担当が保存先から実物を直接再取得する。同一所有者の場合は人的独立性を `LIMITED_SHARED_OWNER` と記録し、技術照合の結果を別に示す。STRICT_INDEPENDENTを要する案件では、指定された独立主体と分離要件を確認する。

## 分類違反と分類未確定

申告値と、証拠や適用規約から確定した最低分類を照合する。該当対象について次の順で判断する。

| 条件 | 分類判定 | 受入とGate | 操作 |
| --- | --- | --- | --- |
| 確定した最低分類より低い申告。所有者指定済みのLevel 3や、所有者指定がなくても規約上の最低Level 3が確定している場合を含む | `FAIL` | 受入 `FAIL`、Gate A/B/C不成立 | 該当操作を停止 |
| 秘密が見つかり、所有者指定前で最低分類が未確定 | `UNKNOWN` | 分類に依存するGate・受入を保留 | 該当する危険な転送・公開・破壊等を停止 |
| 確定した分類と整合する申告 | 分類条件を充足 | 保存・再取得・検証等の条件を個別に判定 | 別途必要な許可に従う |

分類にかかわらず、既知のSHA不一致、保存・検証・必須CI等のFAILは該当する軸に保持し、依存する受入は `FAIL` とする。分類が `UNKNOWN` の間は該当する危険な操作を許可しない。無関係な安全な作業は継続できる。適用版を変える正式な再分類は[互換・移行手順](compatibility.md)に従う。

## 独立再審査と証拠の再利用

別担当の確認で受入・マージ・実行許可の判断が変わり得る変更は、独立再審査を行う。適用版と案件契約の必須CI・レビュー・独立監査を満たす。HEADや保存版が更新された試行は旧結果を保持し、新しい試行として対象を固定する。前提が同じ証拠は元の対象HEAD・レビューを参照して再利用し、HEAD間差分と依存関係から判定に影響する範囲を確認する。Gate Cや実操作の直前にはexpected HEADを確認する。

| 変更 | 確認方法 |
| --- | --- |
| 確認済み結果の転記や意味を変えない誤字修正 | 作業担当が反映後に読み戻し、元レビューを参照する。 |
| テストの期待値・基準データの局所修正で、判定や受入根拠に変更がない | 正常ケースの受理と、既知の異常ケースの拒否を変更範囲で確認する。 |
| 合否・停止条件・受入根拠に影響する変更 | 別担当が問題の再現条件と判断に影響する差分・依存箇所を確認する。 |

独立再審査を依頼する場合は、対象PR・固定HEAD・確認論点を対象PRに記載し、既存の案件文書に検証条件があれば参照する。別担当は同じPRに結果を記録し、作業担当は対象HEAD・結果を読み戻してから完了を報告する。
