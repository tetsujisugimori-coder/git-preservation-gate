# 保全レベルの分類と同名ファイルの扱い（次期改定草案）

未採用・未発効。[Issue #13](https://github.com/tetsujisugimori-coder/git-preservation-gate/issues/13) の分類案に、Level 2保全時の同名ファイルの例外を加える。現行の適用基準は [中央規約 v0.2.0](../v0.2.0/policy.md)。

## 分類案

| 区分 | 適用の目安 |
| --- | --- |
| Level 1 | 通常のコード・文書など。標準のGit管理を適用する。 |
| Level 2 | 非機密の重要成果物・原証拠。再生成できない非機密原本も含め、喪失や破壊の影響に応じた保護を設定する。 |
| Level 3 | 所有者が対象と範囲を指定する特別な機密保護。明白な秘密や法令・契約上の保護義務が判明した場合は、指定前でも該当する転送・公開を止めて個別確認する。 |

分類は成果物・操作ごとに判断する。Level 2の確認は、承認済み保存先への保存、保存先からの直接再取得、案件に必要な同一性検査を対象とする。

## 例外案 — 保存予定名が既存ファイルと重複する場合

1. 元の名前は原物の識別情報として残す。今回の保存対象は既存ファイルと別に追跡し、既存ファイルには上書き・移動・削除を加えない。
2. 承認済みの保存対象・保存先・操作の範囲で別名が使える場合は、同じ保存先に重複しない名前で新規作成する。別名を使うことだけを理由に承認を取り直す必要はない。承認が元の名前やパスに限定される場合は、範囲を確認してから保存する。
3. 新規作成時に同名が生じた場合は、その名前での書き込みを止める。承認範囲内の未使用名があれば、その名前で新規作成する。
4. 保存後の報告には、同名ファイルがあったこと、保存予定名、実際の保存名と所在、保存結果を記載する。保存先からの再取得・照合が必要な案件では、その結果も記載する。既存ファイルとの内容差は、比較を行った場合に確認結果として記載する。

## 草案レビューの確認点

- 同名・内容違いの2ファイルを別々に追跡でき、今回の原物を別名から再取得して照合できること。
- 承認が保存予定名に限定される場合に、別名での書き込みへ進まないこと。
- 別名の候補も書き込み時に先に使われていた場合に、先行ファイルを上書きせず、保存結果に実際に作成した名前が表示されること。
