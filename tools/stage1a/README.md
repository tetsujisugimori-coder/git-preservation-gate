# Stage 1-A 合成Git bundleの限定試験

Issue #7 による所有者承認済みの **実装開始**。本スクリプトは合成用リポジトリを新規作成し、生成したbundleを別ディレクトリにコピー・再取得して照合、空bareへ復元してfsck・refs・到達object IDの一致を検査する。原bundleの複製でのみ破損注入する。既存repoを入力できない設計であり、既存データへの転送・削除・上書きは行わない。

## 実行前の判断基準
- Python 3とGitが必要。各Gitコマンドは最大8秒、再試行0。停止時は成功扱いしない。
- --root は**まだ存在しない新しいディレクトリ**のみ指定できる。親ディレクトリは既存で、試験用に書込み許可されていること。既存rootはexit2で拒否し、cleanupや自動削除をしない。
- ログの `production_permit` は常にfalse。独立人間・資格情報、実際の保持期限、保存先ACL、機密・実案件原物、実運用ゲートは一切検査しない。

例（試験用の親ディレクトリに限定）:

```sh
python tools/stage1a/synthetic_bundle_gate.py --root ./stage1a-new-run
```

開始前に実行場所に同名ディレクトリがないことを確認する。生成した結果はroot直下のresult.jsonとmanifest.jsonに記録される。対象データは合成commitのみ。正常系と故障検知は別項目で出力し、どちらも本番保全PASSとして流用しない。

## 今回の限定範囲
- T01の合成bundle roundtripの一部分、T05の破損コピー検知、T06の期待SHA差替え検知。
- 旧T01/T05/T06の完全契約（別人監査、承認保存先、保持期限、原物認定等）の全実測ではない。T02〜T25を含む未試験ケースはNOT_TESTED。
- 反例の独立oracle、prerequisiteの正式パース、LFS/部分clone、clean-roomのOS隔離、外部プロセスの無起動保証、正式CI、実ケースの技術受入は後続。
- 独立レビューで正常・故障・時間超過・記録欠損等を検査後、Stage 1-A限定受入を別判定。マージは別判断。

### 来歴不足の新しい判断案
[来歴不完全時の判定提案](../../docs/v0.2.0/provenance-exception-proposal.md)。証拠の**内容一致**と、昔の作成者・実行経路等の**来歴完全性**は異なる。欠損部分はUNKNOWNのままにして、独立な安全な作業を止めない。
