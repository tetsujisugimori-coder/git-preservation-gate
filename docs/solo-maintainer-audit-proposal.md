# 単独開発向け保全監査の版付き補訂案 v0.1.1（未採用）

> **状態: DESIGN_PROPOSED / NOT_TESTED。** 本書は中央規約 [v0.1.0](preservation-policy.md) P03〜P07、特にP05の改訂提案であり、採用済み正本を上書きしない。PRレビュー・合成反例・所有者の版採用判断が完了するまでは、v0.1.0の「独立担当者不在はBLOCKED」が有効。Stage 1開始、Gate permit、マージ、実案件への展開の承認ではない。

## 目的と判断基準

開発者が1名の案件で、別人物・別Windowsアカウント・隔離VMが常に必須だと保全が恒常的に停止する。一方、同一主体の自己照合を「第三者による独立監査PASS」と偽ることも許さない。**バイト再取得と内容整合の技術的実証**、**実行セッション分離**、**人・権限・環境の独立性**を別軸で記録し、低リスク範囲のみ明示承認された標準経路を設ける。ハッシュ一致だけでは真正性、削除耐性、保持保証を証明しない。

## 監査モード（案件開始前に固定）

|mode|実行要件|許す判定|適用条件|
|---|---|---|---|
| `SOLO_STANDARD` |同一所有者可。保存Aと照合Bは異なるexecution/attempt・別セッション、別作業領域。Bは承認済み永続保存先を**直接読み**空の別検証先へ取得し、Aの自己申告以外の実物を検証。|技術照合 `PASS` 可。独立性は `LIMITED_SHARED_OWNER`、**第三者独立監査PASS不可**。|事前承認した非機密・低リスク合成証拠等に限定。v0.1.1採用後、案件別例外/モード承認が必要|
| `STRICT_INDEPENDENT` |Aと実在の別責任主体B。Bの主体、取得経路、権限、環境、独自の検査入力/実測を記録。共有基盤は限界として明示。|各検査成立なら技術照合と独立監査の各PASSを別判定|機密、対外保証、署名真正性、改ざん耐性を要する案件、または案件契約で必須のとき|
| `UNDECIDED` |モード未承認、対象分類不明、原物未取得|BLOCKED|便宜的なSOLO降格は禁止|

低リスク判定の根拠は対象の機密性、完全性の影響、公開/転送範囲、保存期間、アクセス制御と所有者承認で固定する。機密混入疑い・ACL不足は公開/転送BLOCKED。本人アカウントしかない事実は強化監査の成功根拠にはならない。

## P05補訂候補（採用前には効力を持たない）

1. **A: 原物の保護・保存**。原ZIP/bundleを再生成せず、元のbytesと既知のdigestを確認する。保存先の許可、容量、アクセス権、保持期限を先行確認し、承認済み新規領域に上書きなしで保存。保存先から再読取り、size/SHA-256/全byteを比較。保存receiptを追記専用で固定。失敗・欠落・再試行の原票を消さない。
2. **B: 別セッションの直接再取得**。別実行IDを持ち、保存先実物を再度開いて新規の空の検証領域へ取得する。Aのローカル作業コピー、Aの照合ログ、単なる同一ディレクトリの複製では不可。Bの手順/入力/結果を別票にし、元の固定記録と保存receiptに突合する。
3. **必須照合**。size/SHA-256/全byte。ZIPの場合は全エントリCRC、entry名の重複、絶対/親参照/危険パス、manifestの集合・サイズ・SHA-256と実内容の整合を別判定。検査不能な項目をPASSへ丸めない。Git bundleはP02/P04の空bare復元、Git object/OID/tree/refs照合を別途実施し、ZIP CRCだけで代用しない。
4. **独立性記録**。owner/OS account/credential、実行セッション、処理経路、検査器の同一性、workspace/ホスト、取得先、保存先への変更権限、共有信頼境界を個別に記録。未観測はUNKNOWN。SOLOでは `independent_person=false`、`same_owner=true` と明記し別人を装わない。
5. **採用後の判定**。案件開始時に `SOLO_STANDARD` が許可され、対象が契約どおり、P03/P04/P08を含む全必須検査が実測PASSなら、技術的なGate BにPASSを許す**提案**。独立者本人性・OS/資格情報分離・不変保存保証の欄はLIMITED/UNKNOWNのまま。STRICT指定時、同一所有者のBではP05 BLOCKED。いずれも正式CI・Gate C・マージ・Stage 1開始許可にはならない。
6. **矛盾と停止**。原物なし・保存先不達・承認/モード未採用はBLOCKED。digest不一致や破損を実証ならFAIL。欠測はNOT_TESTED/UNKNOWN。新しい実物を「紛失した旧原物」として改名・差替えしてはならない。
