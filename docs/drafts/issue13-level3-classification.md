# 次期中央規約の分類改定草案（Issue #13）

**状態:** 検討草案・未採用・未発効。正式運用には[中央規約 v0.2.0](../v0.2.0/policy.md)を適用する。分類の根拠は[Issue #13](https://github.com/tetsujisugimori-coder/git-preservation-gate/issues/13)、同名保存の検討経緯は[PR #23](https://github.com/tetsujisugimori-coder/git-preservation-gate/pull/23)。

## 1. 分類と操作の判断

成果物と操作ごとに、機密性、保存すべき原物への影響、必要な検査を判定する。たとえば同じPRでも、公開文書、非機密の原ZIP、機密原票はそれぞれ判定し、PRの受入に必要な成果物を特定する。

| 条件 | 次期規約での扱い |
| --- | --- |
| 公開でき、Gitから再取得できる通常のコード・文書 | Level 1。Gitと案件別CI・レビューを用いる。追加保存の指定がなければ[Issue #14の既定入力](../stage1b/issue14-level1-defaults.md)を使う。 |
| 非機密の重要な実験原票、原ZIP、Git bundle等 | Level 2。再生成できない原物も含む。承認済みの保存先から直接再取得し、保存版のreceipt、サイズ、SHA-256、必要な全バイト比較と形式別検査を確認する。 |
| 所有者が対象と範囲を明示して特別な機密保護を指定 | Level 3。対象の取扱いに必要な個別承認、実効アクセス権、保持条件、事前に決めた安全条件を確認する。 |
| 明白な秘密や法令・契約上の保護義務が判明 | 所有者指定の有無にかかわらず、該当資料の危険な公開・転送を止め、根拠のある保護義務を適用する。確定した義務は所有者の判断待ちで解除できない。正式な分類と許可経路は該当資料に限って確定する。 |
| 機密性や保護義務の有無が未確定 | 分類はUNKNOWN。該当範囲の危険な公開・転送・破壊を止め、判断に必要な事実だけ確認する。独立した安全な作業は継続できる。 |

氏名の記載がある場合は、記載の文脈、公開範囲、個人の識別可能性、適用される保護義務を見て判断する。分類票には判断理由を記録し、秘密の実値や非公開の原票は公開記録に載せない。

## 2. 非機密原物の保護

再生成不能性、原物の喪失、削除・上書き、改ざんや真正性のリスクがある場合は、該当する原物と操作の保護条件を決める。たとえば重要原ZIPの救済コピーには新規作成のみを許可し、置換を伴う操作は別に判断する。真正性の確認が必要なbundleでは、保存先の実物を使った隔離復元と元のGitオブジェクトの照合を条件にする。追加条件は確認できる根拠と対象リスクを対応づけ、保存の成立に必要な範囲に絞る。

[承認契約](../v0.2.0/authorization-and-rescue.md)の範囲と、実際の保存先・権限・操作の適合を確認する。承認済み範囲は再利用できる。削除・移動・上書きには明示の別承認を要する。監査の独立性は[監査契約](../v0.2.0/gates-and-audit.md)と案件条件に従い、SOLO_STANDARDの技術照合と人的独立性をそれぞれ記録する。

### Level 2の例外 — 承認済みの保存先に同名ファイルがある場合

原ZIPなどの保存予定名が既存ファイルと重複したときは、既存ファイルを上書き・移動・削除せず、元のファイル名を今回の原物の識別情報として記録する。

承認された読取範囲で保存先から既存コピーを直接再取得し、必要な同一性検査と案件の保存条件を満たした場合は、その所在と照合結果を**既存保存の確認**として記録する。今回の新規保存件数には含めない。内容が異なる場合、一致を確認できない場合、または案件の保存条件を満たさない場合は、新規保存が必要なら今回の原物を別名で追跡する。内容差は比較した場合の確認結果を記録し、未比較や確認不能はそのまま記録する。

同じ保存先への別名での新規作成は、保存対象、保存先、主体、操作、名前・パスの制限を含む承認範囲に照らし、範囲内なら既存承認で進める。承認が元の名前やパスに限定されている場合など、別名が範囲外なら保存前に追加承認を得る。

候補名は書き込み時点で未使用の場合にだけ新規作成できる方法で確定する。事前確認の後に同名ファイルが作られた場合は、その候補への書き込みを止め、承認範囲内の別の未使用名を使う。使える候補や既存ファイルを保護できる作成方法がなければ、保存を止めて結果を記録する。

新規作成後は、元のファイル名、保存予定名、実際の保存名と所在、同名による変更理由、保存結果、案件に必要な再取得・照合の結果を報告する。保存できなかった場合は、実際の保存名や新規保存成功を記録せず、停止理由を記載する。

## 3. 記録と移行

追加の分類判断が必要な対象には、次の情報を案件記録へ残す。通常のLevel 1の入口はIssue #14の入力契約を使う。

- 対象成果物、操作、指定がある場合の所有者・指定範囲・指定時点。
- 機密性と、明白な秘密または保護義務が判明・疑われる場合の根拠および停止対象。
- 非機密原物の喪失・破壊・真正性リスクと、当該操作に必要な保護条件・承認の参照。
- 採用版・案件契約、および保存・検証・独立性・受入の各結果。適用外の項目と対象内の未検査を区別する。

正式版を検討する後続PRでは、現行規約の§§2・5・6、Gateの判定と承認契約、Stage 1の分類入力と実装への影響を同じ変更範囲で確認する。旧版の入力は旧版契約で判定し、移行する案件では対象と操作を固定して再審査結果を追記する。既知のSHA不一致などは、分類が変わっても該当する検査軸と受入判定に残す。正式版番号・承認日・発効日・適用範囲は採用時の決定事項とする。

## 4. 実装時の合成検証案

以下は期待結果。実装時に新旧契約それぞれで対照を取る。

| 入力例 | 草案で期待する結果 |
| --- | --- |
| 公開・再取得可能な通常文書、追加保存指定なし | Level 1の既定入力で進める。 |
| 非機密の再生成不能な原ZIP | Level 2。実保存・直接再取得・全バイト比較とZIPの必要検査を要求する。 |
| 非機密の高価値bundleで元Gitオブジェクトの確認が必要 | Level 2。直接再取得後の隔離復元と元オブジェクトの照合を要求する。 |
| 氏名の記載のみで機密性や保護義務が未確認 | 氏名だけでLevel 3を確定せず、文脈と義務を確認する。公開可否も推定しない。 |
| 所有者が秘密原票を特定してLevel 3指定 | 指定された原票・操作に個別の保護契約を適用する。 |
| 所有者未指定の秘密鍵が公開予定のZIPに混入 | ZIPの公開・転送を停止し、該当範囲を隔離して保護判断へ渡す。 |
| Level 2の既存原物を上書きしようとするが、保存承認は新規作成のみ | 該当する上書きは承認範囲外として停止する。 |
| 保存先に同名で中身が異なる原ZIPがあり、別名での新規保存が承認範囲内 | 既存ZIPを保持し、今回の原ZIPを別名で新規保存する。実際の保存名から再取得し、保存後の報告に元の名前・保存予定名・実際の保存名と所在・変更理由・照合結果を記録する。 |
| 保存先に同名の原ZIPがあり、新規保存の承認がそのファイル名に限定されている | 既存ZIPを保持する。別名で保存する前に、その操作が承認されることを確認する。 |
| 保存先から直接再取得した同名の既存コピーが同一で、案件の保存条件も満たす | 所在と照合結果を既存保存の確認として記録する。新規保存件数は増えない。 |
| 既存コピーの内容は一致するが、案件が求める保存条件を確認できない | 既存保存の確認完了にはしない。別名の新規保存が必要なら、承認範囲を確認する。 |
| 同名の既存ファイルと内容を比較していない | 内容差は未確認と記録する。今回の原物の新規保存が必要で別名が承認範囲内なら、既存ファイルを保持して新規作成する。 |
| 別名候補が書き込み直前に先に使われた | 先行ファイルを保持し、承認範囲内の別の未使用名で新規作成する。候補がなければ停止し、保存名や成功を記録しない。 |
| 既知のSHA不一致を含む原物を再分類 | 一致検査のFAILを維持し、依存する受入をFAILのまま記録する。 |
| 公開文書と公開不可の原票が同じPRに含まれる | 文書の独立した作業は継続できる。原票を含む公開と、その原票に依存する受入は保護条件に従う。 |
| v0.2.0で復元不能を理由にLevel 3とした非機密原本の既存記録 | 保存済みの旧記録はv0.2.0の判定を保持する。新しい判定には適用版と対象を固定した再審査が必要。 |
