# v0.2.0 と v0.3.0 の互換・移行手順

[規約本文](policy.md) と同じく、所有者が2026-11-24 JSTに正式採用を承認し、PR #25のmainマージ時に発効する手順。既存案件は、記録された適用版と案件契約で判断する。v0.3.0の初回適用は [採用記録案](adoption-record.md) を参照する。

| 項目 | 互換性と変更 |
| --- | --- |
| Level 1 | 通常のGit管理、既定入力、案件の必須CI・レビューを維持する。追加保存を明示した場合はその操作を別に判定する。 |
| Level 2 / Level 3 | 所有者指定をLevel 3の原則とする。明白な秘密・保護義務は指定に先立って該当操作を停止する。非機密原物の再生成不能性・破壊リスク・真正性に必要な保護はLevel 2の個別条件として扱う。 |
| 同名保存 | 承認範囲内での別名新規作成、既存保存の確認、未完の作成物の記録を明確にする。既存原物の保護と必要な再取得・照合を維持する。 |
| 受入と監査 | 四状態、必須検査、独立性の要件を維持する。独立再審査は判定に影響する差分と依存箇所に絞り、同じ前提の証拠を参照できる。 |
| 入力・実装 | 現行判定器とStage 1の既定版はv0.2.0の契約で扱う。PR #22の `issue13-draft` は合成試作の識別子。v0.3.0の実運用アダプターや入力スキーマの受入は、対象環境・観測・許可とともに案件別に判断する。 |

既存案件を移行する場合は、旧規約と新規約の版・コミット、対象HEAD、成果物・原物・操作、責任者を固定する。該当する保護条件と承認範囲、旧版の結果、根拠を照合する。新証拠・判定・理由を別試行として追記する。既知のFAILは該当する軸と依存する受入に残し、それを解消する証拠が得られた時点で再評価する。旧原物、旧結果、旧承認は記録として保持する。

他リポジトリの適用は [Issue #8](https://github.com/tetsujisugimori-coder/git-preservation-gate/issues/8) の案件単位の手順に従う。対象外の原物は、対象内の判断への具体的な依存や新しい利用が生じた場合にのみ該当範囲を見直す。
