# 保存承認の再利用と原物救済 v0.3.0（正式採用承認版）

[規約本文](policy.md) と同じく、所有者が2026-11-24 JSTに正式採用を承認し、PR #25のmainマージ時に発効する契約。[v0.2.0の承認・救済契約](../v0.2.0/authorization-and-rescue.md) の承認照合、実効ACL・容量・保持の確認、先行救済、過去判定の再審査を継承し、Level 2の同名保存を以下のとおり補足する。

対象・データ分類、保存先、主体・許可操作、実効アクセス権、保持期間、削除・移動・上書き条件、有効期間が一致すれば既存承認を再利用できる。名前やパスの限定も照合する。分類変更後の操作が既存承認の範囲に含まれるかは実施前に確認する。削除・移動・上書きは新規保存とは別に明示承認を得る。

## Level 2の同名保存

1. 保存予定名の衝突を確認した場合に限り、この例外へ進む。保存予定名が未使用で作成の承認がない場合は停止する。同名ファイルは保持し、元のファイル名を原物の識別情報に残す。
2. 承認された読取範囲で既存コピーを保存先から直接再取得し、同一性・過去の保存版receipt・案件の必要な検査を確認する。条件を満たすときは原物IDと元の保存試行に結び付け、所在と照合結果を既存保存の確認として記録する。この確認による新規保存成功件数は0件とする。
3. 内容差・比較未実施・確認不能・案件条件の未達を結果に応じて記録する。新規保存が必要な場合は、同じ保存先で、名前・パスの制限、作成と必要な再取得・照合を含めて承認範囲内の別名を選ぶ。範囲外なら書き込み前に追加承認を得る。
4. 書き込み時点で未使用の名前にだけ新規作成できる方式を用いる。候補が先に使われた場合はその候補への書き込みを止め、承認範囲内の別の未使用名で進める。使える名前や既存ファイルを保護できる作成方法がなければ停止理由を記録する。
5. 新規保存成功は、書き込みが完了し、保存操作に必要な読み戻し照合が成立した時点で記録する。元の名前、保存予定名、実際の保存名と所在、変更理由、保存結果、照合結果を残す。書き込み中断や保存操作の読み戻し不成立で作成物が残った場合は、所在と未完状態・理由を別欄に記録する。該当する新規保存試行の完了済み保存名は空欄、成功件数は0件とし、未完ファイルの削除・移動・上書きには該当操作の承認を適用する。案件の独立再取得・照合と受入は、四状態の該当する軸に別途記録する。
